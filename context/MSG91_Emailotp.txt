==================================================
GOAL
==================================================

Implement this authentication flow:

React Native
    ↓
User enters email
    ↓
MSG91 Mobile SDK sends OTP
    ↓
User receives email OTP
    ↓
User enters OTP
    ↓
MSG91 Mobile SDK verifies OTP
    ↓
MSG91 returns access token
    ↓
React Native sends access token to backend
    ↓
Backend calls MSG91 verifyAccessToken
    ↓
Backend obtains verified identity/email
    ↓
Backend finds or creates/updates the application user
    ↓
Backend establishes the application's normal authenticated session
    ↓
React Native enters authenticated state

MSG91 should be responsible for proving ownership of the email address.

Our backend should remain responsible for application authentication, users, sessions and authorization.

==================================================
SEND OTP
==================================================

When the user submits their email:

1. Validate email format on the client.
2. Normalize the email appropriately.
3. Call MSG91:

OTPWidget.sendOTP({
    identifier: email
});

4. Handle loading state.
5. Handle MSG91 errors.
6. On success, transition to the OTP verification screen.
7. Preserve the email/request context needed for verification.
8. Do not log the OTP.
9. Do not expose MSG91 internals unnecessarily to the user.

Use the request ID returned by MSG91 according to the current SDK/API contract.

Do not invent or assume the response shape. Inspect the installed SDK/types/documentation and implement against the actual response shape.

==================================================
OTP VERIFICATION
==================================================

On the OTP screen:

1. User enters the 6-digit OTP.
2. Validate that it is exactly 6 digits before submitting.
3. Call:

OTPWidget.verifyOTP({
    reqId,
    otp
});

4. Handle loading state.
5. Handle invalid OTP.
6. Handle expired OTP.
7. Handle too many attempts.
8. Handle network/provider errors.
9. On successful verification, extract the MSG91 access token from the actual SDK response.

Do NOT treat successful client-side OTP verification as sufficient to authenticate the application user.

The access token must be sent to our backend.

==================================================
BACKEND API
==================================================

Add an endpoint following the project's existing API conventions.

Preferred conceptual endpoint:

POST /auth/email/verify

Request:

{
    "accessToken": "<MSG91 access token>"
}

If the existing backend uses a different naming convention, follow the existing convention rather than blindly creating this exact path.

The backend must:

1. Validate the request.
2. Reject missing/invalid accessToken.
3. Call MSG91:

POST https://control.msg91.com/api/v5/widget/verifyAccessToken

Headers:

Content-Type: application/json

Body:

{
    "authkey": process.env.MSG91_AUTH_KEY,
    "access-token": accessToken
}

4. Do not expose the MSG91 Auth Key.
5. Do not log the access token.
6. Validate the MSG91 response.
7. Extract the verified email/identity from MSG91's response.
8. Never trust an email supplied independently by the client if MSG91 provides the verified identity.
9. Use the verified identity returned by MSG91 as the source of truth.

Use the project's existing HTTP client/service layer if one exists rather than introducing another HTTP library unnecessarily.

==================================================
IMPORTANT MSG91 FLOW
==================================================

Use this exact conceptual flow:

1. React Native initializes MSG91 Widget SDK with:
   - Widget ID
   - Auth Token

2. User enters email.

3. React Native:
   OTPWidget.sendOTP({
       identifier: email
   });

4. MSG91 sends OTP to email.

5. User enters OTP.

6. React Native:
   OTPWidget.verifyOTP({
       reqId,
       otp
   });

7. MSG91 returns access token on successful verification.

8. React Native sends the access token to our backend.

9. Backend calls:

POST https://control.msg91.com/api/v5/widget/verifyAccessToken

with:

{
    "authkey": process.env.MSG91_AUTH_KEY,
    "access-token": accessToken
}

10. Backend validates MSG91 response.

11. Backend obtains the verified email/identity.

12. Backend creates/finds the application user.

13. Backend issues the application's normal session.

14. React Native stores/uses the application's session and enters authenticated state.
